# Восемь недель с криптой — сайт

Продающая страница персональной программы. Статический сайт без сборки: открывается
как есть, деплоится копированием папки.

```
site/
├── index.html
├── build-single.py          сборка всего в один HTML-файл (dist/index.html)
└── assets/
    ├── css/
    │   ├── tokens.css       токены: цвет, типографика, сетка, ритм, радиусы, motion
    │   ├── styles.css       примитивы и компоненты
    │   └── responsive.css   брейкпоинты, print, coarse pointer
    ├── js/
    │   ├── coinpit.js       физика монет на canvas
    │   ├── warptext.js      искажение заголовка первого экрана (WebGL2)
    │   └── main.js          вся остальная интерактивность
    └── ...
_headers                     кэш и заголовки для Cloudflare Pages / Netlify
worker/                      приём заявок, Cloudflare Worker (рекомендуется)
├── telegram-lead.js
└── wrangler.toml
server/                      то же самое как Render Web Service
└── server.js
render.yaml                  блюпринт Render на сайт и сервис разом
    ├── coins/               98 марок топ-100 CoinMarketCap, 128×128 PNG
    └── img/
        ├── author.jpg       портрет автора
        ├── video-poster.svg постер видеоблока
        └── logos/           логотипы клиентов агентства
```

## Что нужно настроить перед запуском

**1. Приём заявок.** Все кнопки на странице открывают модальное окно с формой
(имя + Telegram). Кнопки тарифов дополнительно передают, какой пакет выбран.
Две константы в начале `assets/js/main.js`:

```js
var LEAD_ENDPOINT = '';   // адрес воркера
var TG_FALLBACK   = '';   // ваш телеграм, запасной путь
```

Форма не обращается к API Telegram напрямую — для этого нужен токен бота, а токен
в клиентском JS виден любому: им можно писать от имени бота, читать входящие
и перевесить webhook. Поэтому токен живёт на сервере, а страница знает только его
адрес.

Готовы два варианта одного и того же сервиса:

| | где | заметки |
|---|---|---|
| `worker/` | Cloudflare Worker | **рекомендуется**: не засыпает, отвечает мгновенно |
| `server/` | Render Web Service | если хочется всё в одной панели с Render; на бесплатном тарифе засыпает |

Cloudflare — три команды, настройки уже лежат в `worker/wrangler.toml`:

```bash
npm i -g wrangler && wrangler login && wrangler deploy
```

Затем `wrangler secret put BOT_TOKEN` и `wrangler secret put CHAT_ID`. Токен
берётся у @BotFather, chat id — у @userinfobot; оба живут в секретах Cloudflare
и в репозиторий не попадают. Свой домен нужно добавить в список `ALLOWED_ORIGINS`
в начале `worker/telegram-lead.js`, иначе форма получит 403.

Render разворачивается блюпринтом `render.yaml` (**New → Blueprint**), но его
бесплатный web service засыпает через ~15 минут простоя и просыпается около
минуты. Страница будит сервис при открытии формы, пока посетитель печатает имя,
— обычно этого хватает, но у Cloudflare такой проблемы просто нет.

`TG_FALLBACK` — ваш ник в Telegram. Если воркер не настроен или запрос не прошёл,
форма покажет прямую ссылку на переписку с уже подставленными данными, чтобы заявка
не потерялась.

От спама в форме стоит honeypot: скрытое поле, которое заполняют только боты.
Воркер отвечает таким запросам `200`, чтобы отправитель не понял, что его отсекли.

**2. Оферта.** Дисклеймер в подвале — не оферта. Договор нужно готовить отдельно
с юристом под выбранную юрисдикцию.

**3. Логотипы клиентов** в секции «Обо мне» — чужие товарные знаки, взятые с сайтов
самих компаний. Убедитесь, что имеете право показывать их в этом контексте.

## Монеты на canvas

`coinpit.js` — вэнилловая реализация ballpit: гравитация, трение, отскок от стен,
попарные столкновения и курсор, расталкивающий монеты. Покоящиеся тела засыпают,
иначе гравитация продолжает накапливаться на лежащем шаре и куча дрожит. Когда все
уснули и курсор не двигается, цикл останавливается полностью — нулевой расход CPU.

Пит создаётся на каждом `<canvas data-coinpit>`:

| Значение | Поведение |
|---|---|
| `data-coinpit="drop"` | монеты падают сверху дождём (первый экран) |
| `data-coinpit="settled"` | физика прокручивается вперёд без отрисовки, куча сразу лежит |

## Заголовок первого экрана

`warptext.js` — порт [WarpText](https://reactbits.dev/text-animations/warp-text) на голый
WebGL2: в проекте нет сборки, React и `ogl`, поэтому компонент переписан, а не подключён.
Математика шейдера та же: медленный дрейф на основе fbm-шума, линза под курсором,
кольцевая рябь и хроматическое расслоение.

Текст остаётся настоящим текстом в DOM — его читают скринридеры и поисковики, он
выделяется мышью. Прячется только краска (`color: transparent`), а поверх ложится canvas.
Позиции символов берутся из самого DOM через `Range`, а не пересчитываются заново:
перенос строк, кегль и трекинг совпадают с вёрсткой на любой ширине.

Деградация: нет WebGL2 — остаётся обычный заголовок; `prefers-reduced-motion` — кадр
рисуется один раз, без анимации; за пределами экрана цикл останавливается.

## A/B первого экрана

Три варианта заголовка, по умолчанию B.

| URL | Вариант |
|---|---|
| `/` или `/?v=b` | **Control** — «Криптой спокойнее пользоваться…» |
| `/?v=a` | **Fear** — «Ваши деньги уже в крипте…» |
| `/?v=c` | **Product** — «Хранить, переводить и использовать крипту самостоятельно» |

`/?ab=1` показывает переключатель, чтобы сравнить варианты вживую.

## Локальный запуск

```bash
python3 -m http.server 4173 --directory site
```

Затем откройте `http://localhost:4173`. Сервер нужен потому, что монеты рисуются на
canvas из локальных PNG — при открытии файла двойным кликом браузер пометит canvas
как tainted.

## Деплой

Любой статический хостинг: GitHub Pages, Render, Netlify, Vercel, Cloudflare Pages,
S3, nginx. Загрузите содержимое папки `site/` — сборка не требуется. Единственная
внешняя зависимость — Google Fonts.

Сейчас сайт живёт на GitHub Pages: https://malboro790.github.io/crypto-8-weeks/
Любой push в `main` пересобирает его примерно за минуту.

Файл `_headers` в корне читают Cloudflare и Netlify: монеты и картинки
кэшируются на год, стили и скрипты — на неделю с проверкой, сама страница не
кэшируется, потому что в ней лежат номера версий ассетов.

### Cloudflare

`wrangler.jsonc` в корне описывает раздачу сайта: Cloudflare теперь поднимает
статику как Worker со статическими ассетами. Без этого файла wrangler
определяет настройки сам на каждой сборке, и результат нельзя воспроизвести.

`.assetsignore` убирает из раздачи то, что публичному сайту не нужно:
исходники сервисов заявок, блюпринт Render, README и сборочный скрипт.
Секретов в них нет — токены живут в переменных окружения, — но и раздавать
их незачем.

Сервис приёма заявок разворачивается отдельно, из папки `worker/`.

### Свой домен

Домен умеют и GitHub Pages, и Render, оба с бесплатным HTTPS. Порядок одинаковый:
добавить домен на стороне хостинга, затем прописать DNS у регистратора.

- **www.example.com** — запись `CNAME` на адрес, который покажет панель хостинга.
- **example.com** (без www) — записи `A` на IP хостинга; точные значения панель
  показывает после добавления домена, из головы их брать не стоит.

Сертификат выпускается автоматически после того, как DNS разъедется, — обычно
от нескольких минут до пары часов.

При переезде на Render не забудьте добавить новый домен в `ALLOWED_ORIGINS`
сервиса заявок, иначе форма начнёт получать 403.

`python3 build-single.py` собирает всё (CSS, JS, монеты в base64) в один
самодостаточный `dist/index.html` — на случай, когда нужен ровно один файл.

## Дизайн-система

Тёмная фиолетовая база с выборочно инвертированными светлыми секциями. Все значения
живут в `tokens.css`, магических чисел в компонентах нет.

- **Шрифты.** Geist — заголовки и текст, Geist Mono — данные (суммы, сети, адреса,
  метки). Обе с полной кириллицей.
- **Типографика.** Шесть ролей: H1 34→66, H2 26→42, H3 18→24, H4 15, text 17,
  subtext 13. Отдельных размеров вне этой шкалы нет.
- **Сетка.** 12 колонок, контент ровно 1280px на широких экранах, гаттер фиксируется
  на 20px от 1320px и ниже начинает сжиматься. Фоны секций всегда во всю ширину.
- **Ритм.** Секции 64→96px, кинематографичные 80→128px, крупные переходы 104→168px.
- **Радиусы.** 12px для панелей и кнопок, 10px для чипов, 6/4 для мелочи.
- **Тема.** Тёмная задана явно через `data-theme="dark"`; светлые секции получают
  `.section--light` и переопределяют палитру на уровне токенов, поэтому компоненты
  не знают, в какой они теме.

## Доступность и поведение

- Семантическая разметка, skip-link, видимый фокус, `aria-expanded` на аккордеоне и меню.
- `prefers-reduced-motion` отключает анимации и скрывает canvas с монетами.
- Без JS: весь контент читается, карта экосистемы остаётся сгруппированным списком.
- Контраст проверен измерением: основной текст 14.7:1, кнопки 5.4:1, акценты 4.6–5.0:1.
- Есть print-стили.
